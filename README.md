# 写作助手 · 马来西亚中国留学生学术写作辅导

> **产品定位**：面向在马来西亚读本科的中国留学生的 **学术写作辅导工具**。
> 帮学生**发现写作问题、学会自己改**，而非代写、不承诺通过任何检测系统。

**纯前端 · 离线运行 · 零依赖 · 不上传任何文本**

六个分析维度：AI 倾向分（6 项可解释文体特征）· 重复风险 · 中式英语风险 ·
文献真实性溯源审查 · **格式规范检查（APA 7 / MLA 9 + 三段结构）** · 院校合规提示

## ⚠️ 先读这个：为什么不做"帮你过检测"

| 常见预期 | 现实 |
|---|---|
| "调 Turnitin 真库查重" | ❌ 不可能。Turnitin/iThenticate 比对库是闭源付费资产，**无任何对个人开放的 API**。声称能调的都是假的。 |
| "降 AI 率骗过 Turnitin" | ❌ 已被技术性封堵。Turnitin 2025-08 上线改写检测；Pangram 第 4 代模型识别 13 款主流降 AI 工具，准确率 98.83%。"改词"路线已死。 |
| "保证过关" | ❌ 后果由学生承担。海外高校普遍将未声明 AI 使用列为学术不端，可判零分/停学/开除，留学生还可能影响签证。 |
| "本工具说没问题 = 能过" | ❌ **本工具是启发式本地分析，不是检测器**。它看不到外部比对库，也无法复现 GPTZero/Turnitin 的判定。 |

**我们做的是**：帮你把文章写得更好、更像你自己写的、更符合学术规范。**责任在你自己手里。**

> v0.2 的重要改动：原来的 "AI 腔指数" 容易让人误读成"及格线"，
> 现已改为 **"AI 倾向分"** 并附**综合判定 + 显式免责声明**（"这不等于真实检测器的结论，
> 也不能预测能否通过"）。每个分数都展开**原始计算指标**，让你能自己判断，而不是盲信一个数字。

## 快速启动

前置要求：**Python 3** 与 **Node.js 18+**（均需在 PATH 上）。无需任何第三方依赖。

```bash
# 1. 构建数据库（数据更新后重跑）
python db/build_db.py

# 2. 验证分析引擎
node db/verify_engine.js

# 3. 启动本地网页
cd web
python -m http.server 8765 --bind 127.0.0.1
# 浏览器打开 http://127.0.0.1:8765
```

> ⚠️ 必须通过本地服务器访问，**不能直接双击 HTML**（浏览器 CORS 会阻止加载 JSON）。

## 文档拖入识别

支持把文件**直接拖进页面**（或点击选择），自动提取正文填入分析框：

| 格式 | 实现 | 实测状态 |
|---|---|---|
| `.txt` `.md` `.csv` `.tsv` `.json` `.log` | 直接按 UTF-8 读取 | ✅ 已实测通过 |
| `.docx` | JSZip 解压 → 抽 `word/document.xml` 的 `<w:t>` | ✅ 已实测通过 |
| `.pdf` | PDF.js 逐页取文本 | ⚠️ 见下方说明 |
| `.html` `.htm` | DOMParser 去标签取正文 | 逻辑就绪 |
| `.rtf` | 去 RTF 控制符（尽力） | 逻辑就绪 |
| `.doc`（旧格式） | 明确拒绝并提示另存为 .docx | 按设计拒绝 |

单文件上限 20MB。

### 关于 PDF 的诚实说明

PDF.js v3 依赖 worker 线程握手。在**受限环境**（如无头 Chrome / 某些沙箱）中该握手可能
长时间不返回。为此解析已加 **20 秒超时保护**，超时会给出明确提示并建议转为 `.docx`/`.txt`，
**界面不会永久卡在"解析中"**。

- 浏览器正常打开本地服务器时 PDF 通常可正常解析；
- 若你的环境解析失败，请把 PDF 另存为 `.docx` 再拖入 —— 该路径已实测稳定。

## 检测引擎（v0.2：可解释 + 多特征）

> **设计原则**：宁可漏报，不可误报。检测器把人类（尤其非母语学生）写作误判为 AI，
> 是这个领域最恶劣的错误（Stanford 研究：主流检测器把 61.22% 的非母语 TOEFL 作文误判为 AI）。
> 因此本引擎**默认保守**：没有内容级证据（命中 AI 套话）时，纯统计信号不会单独把文本判为高危。

### AI 倾向分（`stylometry.js`，6 项可解释特征）

| 特征 | 权重 | 计算方式 | 依据 |
|---|---|---|---|
| **AI 套话密度** | 0.34 | 加权命中 AI 套话库 / 每 100 词 | 最直接的内容级证据 |
| **词汇丰富度** | 0.20 | TTR + hapax legomena 占比 | 跨模型/跨领域**最稳健**信号（arXiv:2606.04177） |
| **句式波动** | 0.20 | 句长变异系数 CV + 相邻句长差 | GPTZero 原始统计层核心指标 |
| **句首/句式多样性** | 0.10 | 句首词去重率 + 最高重复次数 | Stylometry 常规特征 |
| **标点与段落形态** | 0.08 | 分号/破折号/括号频率 + 段长 CV | AI 正式文体几乎不用非对称标点 |
| **可读性与复杂度** | 0.08 | Flesch + 长词占比 | 辅助指标 |

**融合策略**：
- 有套话命中（内容级证据）→ 加权平均 + 峰值加成（≤18），避免被低分项稀释
- 无套话命中 → **严格限幅到 48 分以下**，绝不单独判高危（防误报）

### 重复风险（`duplicate.js`，3 类本地检测）

| 检测项 | 方法 |
|---|---|
| 文内自身重复 | 句级 6-gram 比较，找不同句子间共享的连续片段 |
| 与本地模板重叠 | 与知识库套语做 5-gram 比对 |
| 万能套语密度 | 内置跨学科通用句式清单（`with the development of` 等） |

> ⚠️ **能力边界（界面必须显式声明）**
> - **能查**：文内重复（复制粘贴/自我抄袭）、与本地模板重叠、万能套语密度
> - **查不到**：与外部论文库/网页/期刊的重复（无 Turnitin 比对库）、改写后的语义相似（无向量检索）
> - **本项检测基于本地分析，不能替代 Turnitin/iThenticate，也不能预测查重结果。**

### 实测标定结果（`test/stylo_calib.js` / `fp_check.js`，真跑非推演）

| 样本 | 分数 | 判定 |
|---|---|---|
| 纯 AI · 学术套话 | **77** | 🔴 高 |
| 纯 AI · 空话模板 | **81** | 🔴 高 |
| 纯 AI · 会计师数据风 | **70** | 🔴 高 |
| 人类 · 学术（有引用有犹豫） | 11 | 🟢 低 |
| 人类 · 学生口语化 | 21 | 🟢 低 |
| 人类 · 短学术 | 10 | 🟢 低 |
| 人类 · **非母语学生（语法瑕疵）** | 25 | 🟢 低 |
| 人类 · 混合语言风格（留学生） | 13 | 🟢 低 |

**结论**：3/3 纯 AI 判高危，8/8 人类样本零误报（含专门测试的非母语写作）。

### 匹配引擎的三个工程细节（实测踩坑得来）

- **斜杠歧义**：库中 `"This paper aims to explore/delve into"` 的 `/` 是**短语内"或"**，不是变体分隔。若简单拆分会让 `"delve into"` 单独匹配任意含该词的文本 → 假阳性。修复：当最短变体 < 最长变体 50% 时，只保留最长变体。
- **中文括注污染**：`（高频叠加）` 等注释会进入模式串。修复：先剥离中英文括号内容再匹配。
- **标定方向不能靠直觉**：初版把 TTR 阈值设成 0.48，结果 AI 文本（实测 0.66）判定为"不丰富"却算出 0 分。真跑对照论文结论后才发现阈值错了——**方向对但阈值错，同样会漏检**。

### 拖入识别的第四个工程细节（实测踩坑得来）

- **worker 路径必须相对脚本自身解析**：PDF.js 的 `workerSrc` 是相对**页面 URL** 而非脚本 URL 解析的。写死 `'assets/vendor/pdf.worker.min.js'` 时，若页面不在 `web/` 根目录（如回归测试页在 `test/`），会解析成 `test/assets/...` → 404。修复：用 `document.currentScript.src` 反推 `assets/` 目录。**这个 bug 只有真跑才暴露，静态看代码完全正常。**

## 经验学习（v0.3：浏览器内的自我校准）

用户要求"把检测经验作为记忆放进网站内部并不断进化"。实现为 `web/assets/learner.js`，
但**必须先说清它是什么、不是什么**：

| 是 | 不是 |
|---|---|
| 经验积累 + 规则校准 | ❌ 模型训练（浏览器无算力，不可能训练神经网络） |
| 记录特征统计量，统计规律 | ❌ 记录原文（隐私红线，也偏离"写作教练"定位） |
| 给出调参建议，用户确认后生效 | ❌ 自动调参（错误反馈会污染判定） |

### 工作闭环

```
分析文本 → 抽取特征指纹（脱敏）→ 存入 localStorage
    ↓
用户标注「确实像 AI」/「这是真人写的（误报）」
    ↓
统计各特征在两类样本上的均分 → 算判别力 sep = AI均分 − 真人均分
    ↓
发现误报元凶 / 漏报原因 → 给出建议（不自动应用）
    ↓
用户确认 → 写入阈值 → stylometry.js 立即读取新阈值生效
```

### 关键设计决策

**1. 阈值必须真的生效，否则"学习"是假的。**
`stylometry.js` 不再硬编码阈值，改为 `Learner.getTuning()` 读取；
`Learner` 不存在时回退默认值（保证模块可独立测试）。

```javascript
const T = (typeof Learner !== 'undefined' && Learner.getTuning)
  ? Learner.getTuning()
  : { clicheGate: 20, statCap: 48, boostFactor: 0.35, boostMax: 18, minWords: 120 };
```

**2. 误报归因必须看"判别方向"，不能只看分数高低。**
这是开发中实测发现的逻辑错误：首版归因只统计"哪些特征在误报样本里 ≥60"，
结果把**词汇丰富度**认定为元凶。但实测数据显示该特征 `AI 39 < 真人 76`
（与 arXiv:2606.04177 结论一致：人类词汇更丰富）——它分数高恰恰是**人类**的证据。
若不修正，系统会建议用户压制一个**真正有用的特征**，越"学"越差。

修正后只在 `sep > 5`（方向一致）时才归因，并对方向相反的特征单独说明：

```javascript
if (sep == null)      { culprit[k] = ... }   // 无对比数据，暂计
else if (sep > 5)     { culprit[k] = ... }   // 方向一致 → 元凶
else if (sep < -5)    { inverted[k] = ... }  // 方向相反 → 非元凶
```

**3. 只给建议，不自动改。** 连续几条错误反馈就能把判定带偏，
而检测器的首要危害是误报真人（Stanford 研究：误判 61.22% 非母语作文）。
所有调整需用户确认，且可一键恢复默认。

**4. 隐私：绝不记录原文。** 只存词数、分数、特征值、命中模式**类别名**、长度档位。
端到端测试中专门有一项断言验证经验库不含原文句子。

### 实测验证（全部真跑，非推演）

## 匿名语料贡献（让检测器持续变准）

**要解决的问题**：项目长期缺**现代真实语料**。v0.6 的重标定只用了
「4 篇真人 + 1 篇 AI」，README 里反复承认「不足以精确标定」。
单机积累太慢——需要**多人的匿名特征分布**汇总起来。

### 只导出统计量，不导出原文

| 会导出 | 不会导出 |
|---|---|
| 词数、长度档位 | ❌ **原文**（一个字符都不传） |
| 各特征**原始值**（句式 CV、类符形符比、长词占比…） | ❌ 文件名 |
| 你的标注（真人 / AI / 未标注） | ❌ 精确时间戳（只保留到「日」） |
| 院校（下拉框选的，公开信息） | ❌ 任何可识别你身份的信息 |

**关键设计：必须存「原始特征值」，不能只存折算分。**
折算分 = f(原始值, 当前阈值)，用折算分**无法反推阈值**——
这正是「积累了数据却无法用于重标定」的根因。现已同时记录 `raw` 原始值。

### 关键前提：没有标注的数据是废的

要知道「句式 CV = 0.25 说明像 AI」，前提是**知道这篇到底是真人写的还是 AI 写的**。
只有特征指纹、没有标注，**一条都用不上**。

而事后回去点反馈按钮的转化率极低。所以在**上传完成、用户最清楚来源**的时候问一句：

> 这篇是你自己写的吗？　[我写的]　[AI 生成的]　[跳过]

一次点击，不阻断流程（可跳过），标注直接写进该条记录。

> ⚠️ **不要走捷径**：不能假定「上传的都是学生自己写的」。
> 用户上传 AI 生成的文章来测试检测器是完全正常的用法 ——
> 把这些标成「真人」等于告诉检测器「AI 特征 = 人类特征」，**越学越瞎**。
> 标注只能来自用户明示。

### 三条隐私红线

1. **导出 ≠ 上传**。点「导出匿名贡献包」只在本机生成一个 JSON 文件，
   不发起任何网络请求。是否交出去完全由用户决定。
2. **匿名 ID 可重置**。`anon-xxxxxxxx` 在本地随机生成；
   点「重置匿名 ID」后，此后导出的数据与之前的贡献**无法关联**（相当于撤回）。
3. **不收集原文**。这一点写进了模块注释、界面提示和测试断言。

### 怎么用（维护者视角）

```bash

node tools/aggregate_contributions.js --dir ./contributions --min-n 3
```

## 真实语料评估与特征重标定（v0.4：用数据纠正方向）

v0.3 之前，检测器的特征方向**照搬了一篇论文的结论**（arXiv:2606.04177：
"人类 TTR/hapax/实词密度 一致高于 AI"）。这在**本项目的数据上是错的**。

### 首轮评估暴露的问题

用 72 篇公版真人语料（Project Gutenberg）+ 9 篇 AI 样本跑评估，结果：

| 指标 | 首轮实测 |
|---|---|
| 漏报率（AI 未识别） | **88.9%**（9 篇只抓出 1 篇） |
| 误报率（真人被判中/高） | **11.1%**（72 篇误判 8 篇） |

**根因**：`lexical`（词汇丰富度）方向反了。实测：

| 指标 | AI | 真人 | 论文假设 |
|---|---|---|---|
| TTR | **0.759** | 0.579 | 人类更高 ❌ |
| hapax | **0.635** | 0.436 | 人类更高 ❌ |
| 实词密度 | **0.714** | 0.464 | 人类更高 ❌ |
| 平均词长 | **6.89** | 4.70 | — |

原因：该论文测的是**等长、同领域**文本；本项目的对照组存在
**时代/文体偏差**（19 世纪英文重复率高、虚词多、句子长，天然拉低 TTR）。

### 用实测数据重新标定

对每个候选特征计算 10%-90% 分位的**重叠比例**，用数据决定方向与权重：

| 特征 | AI 均值 | 真人均值 | 方向 | 重叠比例 | 权重变化 |
|---|---|---|---|---|---|
| 标点（分号/破折号/括号） | 0.00‰ | 2.37‰ | 真人高 | **0.000** | 0.08 → **0.16** |
| 句式波动 CV | 0.236 | 0.495 | 真人高 | **0.000** | 0.20 → **0.26** |
| 词汇丰富度 | 0.759 | 0.579 | **AI 高** | **0.000** | 0.20 → 0.18（反转） |
| 词形复杂度（长词） | 43.3% | 16.0% | AI 高 | **0.000** | 0.08 → 0.10 |
| 虚词占比 | 28.6% | 53.6% | 真人高 | **0.000** | 0.10 → 0.08 |
| AI 套话密度 | 14.9 | 1.0 | AI 高 | 弱 | 0.34 → **0.12** |
| 句首多样性 | 0.873 | 0.820 | — | **0.800（不可用）** | 降权 |

### 融合策略重构

旧策略把 `cliche`（套话）当唯一"内容级证据"闸门，无套话命中就限幅 48 ——
这正是 88.9% 漏报的直接原因（9 篇 AI 中 5 篇零套话命中）。

新策略：用**实测重叠 0.000 的强特征组**做投票：

```javascript
const strongKeys = ['punct', 'burstiness', 'lexical', 'readability', 'starter'];
const strongVotes = signals.filter(x => strongKeys.includes(x.key) && x.aiScore >= 65).length;

if (clicheScore >= T.clicheGate)      score = weighted + boost;      // 套话级证据
else if (strongVotes >= 3)            score = Math.max(weighted, strongAvg);  // 3+ 票放行
else if (strongVotes === 2)           score = Math.min(..., 64);     // 2 票封顶 64
else                                  score = Math.min(weighted, T.statCap);  // 保守限幅
```

### 短文本鲁棒性修正

实测发现：60 词的真人段落也会因"零分号"拿 88 分——标点密度在短文本上
区分的是**文本长度**而非作者身份，会误伤非母语学生的简短写作
（Stanford：误判 61.22%）。故加两条修正：

```javascript
// 1) 标点特征按词数衰减：>=200 词全额，<100 词降到 40%
const punctReliability = wordCount >= 200 ? 1.0
  : clamp01((wordCount - 40) / 160) * 0.6 + 0.4;

// 2) 短文本整体置信度收缩：<120 词按比例下调
if (wordCount < 120) {
  const shrink = 0.65 + clamp01((wordCount - 40) / 80) * 0.35;
  score = score * shrink;
}
```

### 最终实测结果

| 指标 | 修正前 | 修正后 |
|---|---|---|
| 长文本漏报率 | 88.9% | **22.2%** |
| 长文本误报率 | 11.1% | **0.0%** |
| 短文本误报 | 1/5 | **0/5** |
| 精确率 | 11.1% | **100%** |
| 真人分数范围 | 17-46 | **1-33**（全部低风险） |
| AI 分数范围 | 27-75 | **48-89** |

> ⚠️ **必须承认的局限**：真人语料是 19 世纪英文，与现代学生写作有时代偏差，
> 放大了句长类特征的区分度。上述数字是**该对照组**上的表现，
> 不能直接外推到留学生作业场景。其价值在于**暴露并修正了特征方向错误**。
> 详见 `test/corpus/README.md`。

## 文献真实性溯源审查（v0.5：查出 AI 编造的文献）

**要解决的问题**：AI 编造文献（幻觉引用 / fabricated citations）。
AI 写文章时会生成"看起来完全像真的"的引用 —— 作者、年份、期刊名、DOI、
页码一应俱全，实际上这些文献**根本不存在**。这是 AI 写作最难被表面语法
检查发现的缺陷，也是学生被判学术不端的常见原因。

### 首先说清能力边界（这一条最重要）

| 本模块**做** | 本模块**不做** |
|---|---|
| 把"形态上像幻觉引用"的地方挑出来 | ❌ 联网核验文献是否真实存在 |
| 检查正文引用与文献列表是否对得上 | ❌ 判断文献内容是否被正确引用 |
| 给出核验清单，交给人逐条查 | ❌ 给出"真假"结论 |

**为什么不联网核验**：产品是纯前端离线运行（无服务器）；Crossref / doi.org /
Google Scholar 均无免费开放的浏览器直连跨域接口；即便能调用，也无法凭标题
猜出"这篇到底存不存在"—— 必须人去看。所以它输出的是**「可疑 / 需人工核实」**，
**不是「确定为假」**。这个限定在界面上用醒目样式常驻声明。

### 幻觉形态库（8 类，`data/F_citation_checks.json`）

| 编号 | 类型 | 严重度 | 说明 |
|---|---|---|---|
| HC01 | 作者名存疑 | 中 | `et al.` + 年份组合，模型只需编个像样的姓氏 |
| HC02 | 期刊名泛化 | 中 | 「International Journal of … Research」听起来权威但可能不存在 |
| HC03 | DOI 形态异常 | **高** | 幻觉重灾区：格式看似标准，后缀常过短、纯字母 |
| HC04 | 顶刊卷期异常 | 中 | Nature/Science 被当权威背书，卷期页码往往对不上 |
| HC05 | 统计数字无出处 | **高** | 出现具体百分比但附近无引用 —— AI 编数据的分水岭 |
| HC06 | 「研究表明」类空引 | **高** | 有背书但不说谁的研究，AI 极爱用 |
| HC07 | 「大量研究」模糊量化 | 中 | 「越来越多的研究表明」同样是空引 |
| HC08 | 作者名重复异常 | 中 | 引用集中于少数常见姓氏，真实综述作者谱更分散 |

### 九项可疑度信号

`no_reference_section`(18) · `dangling_marker`(22) · `orphan_entry`(10) ·
`doi_unformatted`(16) · `unsourced_number`(20) · `vague_attribution`(14) ·
`author_concentration`(12) · `year_anomaly`(14) · `pattern_high`(16)

合计后归一化到 0-100 的**可疑度**。其中 `dangling_marker`（正文引了、
文献列表里没有）权重最高 —— 这正是 AI 幻觉引用的典型形态。

### 三个实测踩坑（都是真跑才暴露的）

**1. 双重转义让 8 条正则全部失效。**
在 JSON 里写 `"pattern": "et al\\\\.\\\\s+..."`，`JSON.parse` 后得到的是
`et al\\.\\s+...` —— 反斜杠被当成字面量，正则永远匹配不到。修复：JSON 中
应写 `\\s`（解析后即 `\s`）。**症状是"规则数 8、命中数 0"，静态看代码完全正常。**

**2. 正文特征不能把参考文献列表一起扫。**
初版对**全文**跑"无出处数字"检测，结果一篇规范引用的文本被检出 **12 处**
无出处数字 —— 全部来自 References 里的 `77(s-1)`、`35-59` 这类卷期页码。
修复：先用 `REF_HEADING_RE` 定位列表起点，**正文特征只在正文上计算**。

```javascript
const ref = findReferenceSection(text);
const body = ref.has ? ref.bodyText : String(text);   // ← 关键
const unsourcedNums = findUnsourcedNumbers(body);     // 不再扫列表
```

**3. 叙述式引用的作者归属错了，导致误报"孤立条目"。**
`Dechow and Dichev (2002)` 的**第一作者是 Dechow**（APA 索引依据），
但初版正则只抓了紧邻年份的那个姓（Dichev），与条目
`Dechow, P. M., & Dichev, I. D. (2002)` 对不上 → 被误报为"该条目正文未引用"。
修复：显式捕获「姓 (and/&) 姓 (年)」整体，优先取第一个姓，并在匹配时
同时比对第一个姓、第二个姓与完整原文。

**4. 括号内多条目被漏抽。**
`(McNichols, 2002; Ball & Shivakumar, 2006)` 初版只捕获第一个。
这会导致本该发现的悬空引用查不出来。修复：正则支持 `;` 分隔的多条目，
捕获后逐条展开。

### 融合进结果页

- 评分环新增 **「文献可疑度」** 卡片（无引用时显示 `N/A`，不是 0）
- 结果区 **⑧ 文献真实性溯源审查** 区块：
  可疑度概览 → 能力边界 → 判定依据（逐项加权）→ DOI 逐条核查（**每个都带
  doi.org 直达链接**）→ 悬空引用 → 孤立条目 → 无出处数字 → 空引 → 年份异常
  → 命中的编造形态 → **手动核验清单**
- 整篇文章**没有任何引用**时，明确标注「本项不适用」，**不判为低风险**
  （没有引用不等于安全 —— 若作业要求引用却没有，本身也是问题）

## 格式规范检查（APA / MLA / 三段结构）

**要解决的问题**：作业评分标准里常见的两条硬性要求 ——
「掌握基本的 APA/MLA 引用格式」与「内容结构清晰：Introduction / Body / Conclusion 缺一不可」。
这两条是**格式与结构合规**问题，与「是不是 AI 写的」「有没有抄」是不同维度，故独立成模块。

### 首先说清能力边界

| 本模块**做** | 本模块**不做** |
|---|---|
| 识别你用的是 APA 7 还是 MLA 9 | ❌ 联网核验文献真伪（那是上一模块的事，且同样不联网） |
| 提示引用条目是否符合格式骨架 | ❌ 判断引用内容是否被正确使用 |
| 检查 Intro / Body / Conclusion 是否齐全 | ❌ **判分**，也❌不替代导师的 rubric |

输出语义是**「建议核对清单」**，不是分数标签。规则依据 APA 第 7 版与 MLA 第 9 版
官方规范，**逐条对照大学图书馆官方指南核实**（见 `data/H_format_rules.json` 的
`meta.verified_note`），未凭记忆书写。各校各导师要求可能有差异，界面上常驻声明
「请以你的 rubric 为准」。

### 为什么独立成 `format.js` 而不是扩展 `citation.js`

两者职责与输出语义完全不同，混在一起会互相污染：

| | `citation.js` | `format.js` |
|---|---|---|
| 问的问题 | 这条引用**是不是编造的**？ | 这条引用**写得合不合规范**？ |
| 输出 | 可疑度（越高越可疑） | 合规问题清单（核对项） |
| 方向 | 风险 | 规范 |

### 规则库（`data/H_format_rules.json`）

- `styles`：APA 7 与 MLA 9 两套体系，各含 `in_text_rule` / `reference_rule` / `checks`
- `structure`：Intro / Body / Conclusion 三段，各带 `detect` 标记词
- `common_mistakes`：CM01–CM07 常见错误
- `guide`：9 步自查清单

### 已实现的检查项

**体系识别**：正文括注形态（`(Smith, 2020)` → APA；`(Smith 15)` → MLA）
与参考文献页标记（`References` → APA；`Works Cited` → MLA）双向投票；
两者指向不同体系时单独报**体系冲突**（学生最常见的混用错误）。

**格式合规**：
- `DOI_BARE`：DOI 未写成完整链接 `https://doi.org/…`
- `DOI_PERIOD`：APA 7 明确要求 DOI 后**不加句点**
- `RETRIEVED_FROM`：APA 6 遗留写法，APA 7 已取消
- `REF_ETAL`：参考文献列表里误用 `et al.`（应列全作者）
- `MLA_TITLE_WRONG` / `APA_TITLE_WRONG`：参考文献页标题与体系不匹配
- `NO_REF_SECTION`：正文有引用但完全没有参考文献区

**三段结构**：支持三种作业形态 —— 带小标题、经典三段式（各一段）、多段论述；
**表格 / 清单型文档明确标注「本项不适用」，而不是扣分**。

### 六个实测踩坑（都是真跑才暴露的）

**1. 小标题不能用「短 + Title Case」推断。**
财务报表 / 表格里的行标签（`assets` / `cash` / `total` / `equity`）会全部中招，
把正文段落吃光，导致误报「缺 Body」。实测一份表格型会计作业报出 60+ 个伪标题。
修复：**只认明确的章节名白名单，不做风格推断**。

**2. 表格 / 清单型文档应判「不适用」，而不是判缺结构。**
判据：排除标题后，若 ≥20 词的实质段落少于 2 个，视为非叙述文体 → 本项不适用。

**3. 引言判定会把标题当成第一段。**
文档开头常是标题 / 目录 / 分隔线（都很短）。若直接看「第 1 段」，
真正的 46 词开篇会被跳过，误报「缺 Introduction」。
修复：**先跳过开头的短段（<20 词）**，再看是否有引言标记。

**4. 经典三段式作业被误报「缺 Body + 缺 Conclusion」。**
两处独立缺陷叠加：
- `body = contentParas.slice(1, -1)` 在三段式里只剩 **1 段** → 达不到「≥2 段」门槛；
- `conclusionOk` 要求 `contentParas.length >= 4` → **三段式永远拿不到结论分**。

修复：显式识别三段式（恰好 3 个实质段落且首尾分别是首末段）时，
**中间那一段即构成 Body**；结论判定改为要求**有区分力的证据**
（显式标记词 / 末段明显短于正文均长 / 含总结展望句式），
**不接受单纯的位置**——否则真正缺结论的文本会被误判为齐全。

**5. 只按「是不是最后一段」判结论，会漏掉真正缺结论的文本。**
这条是修 #4 时**自己引入的假阴性**：把判据放松成「末段是实质段即算结论」后，
一篇确实没有结论的 4 段文本被判为「齐全」。
→ **教训：放松阈值必须同时验证反向案例，不能只看正向是否通过。**

**6. 「无可判断项」不得给满分。**
初版只要 `applicable` 就算分数，于是一段「识别不出体系 + 结构不适用」的短文
拿到「格式规范度 100」——等于给无法判断的文本打满分。
修复：只有**确实做出了判断**（识别出体系 / 结构可判 / 查出问题 / 有参考文献区）
才给分，否则显示 `N/A`。

### 融合进结果页

- 评分环新增 **「格式规范度」** 卡片（无可判断项时显示 `N/A`，不是 100）
- 结果区 **⑨ 格式规范检查（APA / MLA / 结构）** 区块：
  体系识别 + 置信度 → 事实 chips（参考文献区 / 问题数 / 结构）→ 能力边界声明
  → 结构三段逐项 ✓/✗（带判据说明）→ 格式问题清单（带示例）→ **9 步自查清单**

## 开发/测试环境的沙箱坑（实测踩坑得来）

在本机沙箱内做浏览器验证时踩到这些坑，记录下来避免重犯：

1. **后台服务器会随 Bash 调用结束被杀**。`nohup ... &` 跨调用依然失效 → 必须把「启动服务器 + 跑 Chrome + 关服务器」写在**同一次** Bash 调用里。
   → 更稳的做法：让测试脚本**自己拉起服务器并自检**（见 `cdp_learn.js` 的 `ensureServer()`）。
   否则会出现「服务器没起 → `Page.navigate` 落到 `chrome-error://chromewebdata/` →
   报错却是 `#learnerFull 为 null`」这种**误导性失败**，排查成本极高。
2. **curl 需加 `--noproxy '*'`**。否则 127.0.0.1 会被代理拦截，返回 `502`（看起来像服务挂了，实际是代理）。
3. **`--dump-dom` 在无头模式下可能返回空**。改为 `--screenshot` 截图后读图更可靠；反过来，服务器存活时 `--dump-dom` 是正常的。
4. **Chrome 154 起 `/json/new` 接口受限**，直连会返回 `Using unsafe HTTP verb GET to invoke /json/new`。
   正确做法：启动 Chrome 时**直接在命令行传目标 URL**，再从 `/json/list` 里取该标签页的 `webSocketDebuggerUrl`。
5. **`app.js` 的函数不挂在 `window` 上**（文件作用域），外部测试脚本用 `window.renderAnalysis` 会得到 `undefined`。
   验证交互应走**真实页面 + 真实点击**（CDP `Runtime.evaluate` 执行 `element.click()`），
   而不是在测试页里直接调内部函数。这与之前 `Stylometry` 的陷阱同源：**const/function 声明不会自动上 global**。
6. **Node 22 内置 `WebSocket` 与 `fetch`**，无需安装 `ws`/`puppeteer`，
   可直接用 CDP 做端到端交互验证。
7. **无头模式下 `alert()` 会永久阻塞主线程**。
   `btnAnalyze` 在文本 <20 词时调 `alert()`，无头 Chrome 会一直等对话框被关闭，
   于是后续所有 `Runtime.evaluate` / `captureScreenshot` **全部超时**，
   表现为「页面卡死」，极易误判成死循环或渲染问题。
   → 修复：监听 `Page.javascriptDialogOpening` 并自动 `Page.handleJavaScriptDialog`。
8. **分数环在「被守卫拦下」时保留上一次的值**。
   短文本触发 `<20 词` 守卫时函数早退、页面不重新分析，`#scoreFmt` 仍是上一篇文章的结果。
   这是**正确行为**，但测试断言不能拿它当本次结果 —— 应断言「守卫是否触发」。
